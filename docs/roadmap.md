# 演进路线

已完成的 0.4 核心：统一节点/关系/引用/视图、25 种内置类型、声明式扩展类型、三维状态、树约束、事务服务、JSON 存储、CLI、本地编辑工作台和 LittleLoop 描述链验证。

后续按真实项目问题推进：

1. 编辑体验：在已支持的三种树、类型表单、关系和引用编辑之上，增加 Markdown 预览和事务差异审阅。
2. 描述精度：接口失败语义、不变量、流程分支、状态迁移的深层 schema；关系端点类型与领域约束。
3. 演进分析：Git 基线差分、版本化引用解析、文件变化监测、下游 stale 建议及批量重评。
4. Agent 工作流：按任务组装上下文，生成有依据的变更提案，提供可审阅的批量操作；所有入口复用核心服务。
5. 模型规模：测量完整快照读取与校验成本，按证据添加索引、分片或存储后端。
6. 可持续升级：版本迁移预览、迁移测试与回退机制。当前重建授权不延续到后续版本。

每次 LittleLoop 中出现难描述、重复描述、易误解的情况，先记录具体样例，再决定是否修改核心类型、扩展 schema、关系、查询或交互。不要只因能添加字段就扩展协议。
