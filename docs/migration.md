# 0.3 → 0.4 迁移方案

本次是经用户明确批准的重建，不是兼容迁移：放弃旧 TOML 记录及其工具历史，建立 format 3 项目模型。不会重写 Git 历史、删除仓库或回滚项目源代码。

## 已执行的切换

1. 新权威入口是 SPEC.md、公共核心与 `.singularity/model.json`。
2. 原 `--records`、create/links/confirm/history 等旧接口退出；新接口统一为 `--project` 与 apply 事务。
3. 旧自描述 TOML、旧示例、旧模板和 Angular 编辑器退出当前工作树，避免两种模型同时被误认为权威。
4. 本仓库建立直接引用当前用户授权的新意图节点；不把十条旧候选自动确认。
5. LittleLoop 从现有设计文档建立新的模型。候选意图未确认，任务未实现，实验未执行。
6. 旧图形编辑入口切换到只读 format 3 预览，后续图形编辑器独立迭代。

## 新项目/外部旧项目操作

本轮不自动修改本仓库和 LittleLoop 之外的项目。新项目运行 init；需要重建的旧项目由所有者明确决定是否保留旧文件，移除旧入口后运行 init，再用 apply 导入经审阅的新对象。init 不覆盖已有 model.json；不存在静默自动迁移。

导入顺序可以是节点/引用/关系/视图的单次批量事务，最终整体通过校验即可。不要将旧 Confirmed 文本批量转换成人类授权。新授权必须有实际依据。

## 验收

- 旧格式给出明确错误，不能被猜测解释。
- 新模型读写、状态独立、树约束和引用完整性通过测试。
- dry-run 不写磁盘；revision 过期、锁冲突、写入失败不覆盖模型。
- LittleLoop 可查询完整设计上下文、契约下游、三种树与未决假设。
- README、Agent 入口、启动器和模板均指向 format 3。

## 此后格式升级

本次授权不代表今后都可丢弃数据。未来默认需要：版本检测 → 变更报告 → 迁移预览 → 校验 → 原子替换 → 迁移结果报告。破坏性丢弃须有当次授权。本轮未实现通用迁移引擎，也不保留 format 1/2 适配器。
