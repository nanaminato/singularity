# 0.4 核心架构

## 分层

| 层 | 实现 | 边界 |
| --- | --- | --- |
| 模型 | tools/singularity_core/model.py | 类型目录、字段/状态/引用/图校验，无文件 I/O |
| 存储 | tools/singularity_core/storage.py | JSON 快照、revision、锁、原子替换 |
| 应用服务 | tools/singularity_core/service.py | 批量 put/delete、角色与依据、整批验证 |
| 查询分析 | tools/singularity_core/query.py | 上下文、影响、树投影、引用诊断、描述缺口 |
| CLI | tools/singularity.py | 参数与 JSON 输入输出，调用公共核心 |
| 浏览器 | tools/singularity_web.py | 只读模型预览和 GET /api/model |

Python 3.11+，无第三方运行依赖。TOML、旧 Angular 页面与旧数据模型退出当前架构。浏览器使用 textContent 显示不可信文本；不直接渲染 HTML。完整图形编辑器之后通过同一应用服务接入。

## 当前存储决策

单个 JSON 快照使跨节点和边的事务有清晰的一致性边界，且无需部署数据库。代价是每次读取、写入、校验均涉及完整快照，不适合无限扩大的运行时数据。当前目标是项目构建描述。大规模项目先测量模型大小、查询延迟和写入冲突，再决定分片、索引与数据库后端。

模型定义独立于存储路径。未来后端必须保留全图约束、批量原子性、revision 冲突行为和角色校验。不得通过更换入口绕开服务规则。

## 查询与信任

影响分析给出已声明关系上的解释路径，不宣称语义完备。确认依据是人的实际决定，actor 只作标记。验证状态需要证据链接，但工具不能凭链接存在断定证据真实。外部引用只保存定位；联网抓取、版本内容读取和符号校验属于后续适配器。

## 项目反馈循环

在 LittleLoop 中先发现表达问题，形成模型节点或测试案例；判断应改类型、关系、校验、查询还是交互；提出并实现模型变化；运行回归和真实项目查询；记录新能力和未解决问题。无需因为每个新概念都添加专用核心类型，优先利用声明式 x_ 类型验证需求。
